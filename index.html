IPAY Backend

API reference for the IPAY backend, an ASP.NET Core Web API that recreates the Amazon storefront structure, including catalogue, cart, orders, seller flows and a films and series section.

Solution layout

Domain

IPAY.Domain

Entities (users, shop, media), enums and the repository and service contracts. No dependencies on other layers.

Application

IPAY.Application

Business logic: services, DTOs, FluentValidation validators, AutoMapper profiles and options.

Infrastructure

IPAY.Infrastructure

Firestore repositories, identity and JWT, SMTP email (MailKit), Cloudinary images, caching and authorization policies.

WebApi

IPAY.WebApi

HTTP entry point: controllers, validation filter, Swagger UI and application start-up.

UnitTests

IPAY.UnitTests

NUnit and Moq tests for services, validators, entities, Cloudinary and controllers.

Dependency flow

// each arrow means "references"; inner layers never know about outer ones WebApi -> Infrastructure -> Application -> Domain WebApi -> Application UnitTests -> all four projects

Feature areas

Authentication

Registration, login, Google sign-in, two-factor delivery, password reset, email and phone change. See Services.Auth.

Shop

Products, categories, manufacturers, cart, orders, addresses and ratings. See Services.Shop.

Media

Films, series, episodes and genres. See Services.Media.

Sellers and admin

Seller requests, seller products, user management and bans. See Entities.Users.

Configuration

Third-party settings such as the OMDb API key are described in Configuration. Keep real keys in user secrets or environment variables, never in appsettings.json.
